# SignaLens MVP 验证记录

日期：2026-09-20。范围：本机本地 API 与合成输入；此记录不含 API key、真实研究资料或用户文件。

## 已完成

- `uv run pytest -q`：20 项通过。覆盖固定三档契约、拒绝异常 Jev 响应、连接失败有限重试、PDF 全文与选页、Word 正文/标题/表格、超长拒绝、API 错误与来源限制、评测脚本。
- JavaScript、扩展 manifest、Shell 脚本语法检查通过。Tesseract 可用语言包括 `eng` 与 `chi_sim`。
- 用 macOS `textutil` 生成一份合成旧版 `.doc`，提取层正确识别其 OLE 文件头并取出全部测试文字；这不代表复杂旧版 Word 文件的批量保真度已验收。
- 本地 API 启动后，`/api/health` 返回 `ready`；普通网页来源请求返回 `FORBIDDEN_ORIGIN`。
- 首轮本地 API 直连：五条合成文本、一份合成 DOCX、一份合成扫描 PDF，七次调用均返回 HTTP 200 和固定三档之一。文本样例实际覆盖 `RESEARCH / KEEP / SKIP`；扫描 PDF 返回 `ocr_pages=[1]`，DOCX 和 PDF 都以 `whole_document_text` 评估。其后还完成了 Chrome 侧边栏的真实调用，未将这些重复样例用于质量指标。
- 一条无关的合成文本内含“强制输出 RESEARCH”指令，实际返回 `SKIP`。这只是一条挑战样例，不证明全面抵抗提示注入。
- 首次合成文本从本地请求发出到收到结果约 3.1 秒；另外三条已计时的合成文本约 1.8–1.9 秒。样本量与运行环境不足以计算产品 P50/P95 验收结论。
- Chrome 已通过“Load unpacked”加载本地 MV3 扩展。实际侧边栏确认连接本地 API，保存 Context，完成粘贴文本、合成 DOCX 和合成扫描 PDF 的上传评估；结果显示三档、模型把握度、整份文档可提取文字范围及 PDF OCR 提示。关闭再打开侧边栏后 Context 仍在，原输入未恢复；工具栏入口可打开侧边栏。
- Chrome 扩展详情页确认站点访问范围为 `http://127.0.0.1:8765/*`，隐身模式未启用，额外的 file URL 访问已关闭。第一次侧边栏 DOCX 请求遇到 Jev 临时连接失败，界面显示错误且未伪造标签；重试成功。
- 源码包包含实施方案，不含 `.venv`、缓存、密钥文件或输入资料。
- 新增 36 条预先冻结的合成文本诊断，首轮 33 次返回三档、3 次服务失败；详细混淆矩阵、争议案例及限制见早期合成样本诊断记录。服务重启后，同一批旧样本做连接回归，36/36 次返回三档，API P50 306 毫秒、P95 893 毫秒；这是该本机、该批输入的一次连接复测，不保证长期可用率。
- 另外冻结 48 条中、英、西、日语与四种 Context 交叉的自拟文本：v1 首轮三档一致 42/48，6 条 `KEEP` 误判为 `RESEARCH`。因此将规则升级到 `triage-2026-09-20-v2`，明确“只公布未来日程、无新事实或重大时间变化”应保留为 `KEEP`。在改规则前已冻结另一批 48 条不同领域/Context 的合成文本；v2 首轮 48/48 与自拟标签一致，先前 6 条错判的定向回归也全部改判为 `KEEP`。这只是实施者自拟标签的一致率，**不能称为真实投研正确率达到 90%**；数据、哈希、逐条结果见[多语言评测报告](multilingual-evaluation-2026-09-20.md)。
- 中、英、西、日语各一份 Word 和 PDF 的首组 8 份合成文件，全文提取与原文字一致，8/8 次本地上传得到预设标签；随后增加语言、两种 Context、两种格式和 `RESEARCH / KEEP` 交叉的 16 份文件检查，提取 16/16 完整，但分类 14/16。两条早期原型资料被误判为 `RESEARCH`，因此文件口径修为 v3；该两条定向回归为 2/2 `KEEP`。修改前冻结的 24 份全新文件，离线提取 24/24 完整、实时 Jev 24/24 返回三档、三档一致 22/24（91.7%）。两条错误为保险 Context 下的西语和日语无关信息；同文字粘贴测试仍错，说明不是文件提取导致。先前 16 份文件内容重复文字封存集，不能重复计算为独立质量样本。
- 把旧合成样本中“长背景里一条重要线索”制成 Word，v3 在全文范围返回 `RESEARCH`；这是单条聚合规则的事后回归，不计入独立质量分母。
