# SignaLens 多语言与 Research Context 评测

日期：2026-09-20。范围：本机 API 与自拟合成材料。所有原文、Context、预设标签、文件哈希、首轮预测和失败记录保存在 [测试数据](../eval/synthetic_2026-09-20/)；机器可读汇总为 [评测结果 JSON](../eval/synthetic_2026-09-20/summary.json)。文件、公司代号和数字均为虚构，不是市场事实或投资建议。

## 结论与口径

用户新增的正式目标是**端到端三档正确率至少 90%**：`RESEARCH / KEEP / SKIP` 与事先冻结的人工标签完全一致的次数，除以全部有效提交次数；服务或提取失败计为未正确分流。正式放行须用真实来源、独立研究员标注的封存样本，并按语言、格式和 Research Context 分组检查。本报告中的标签由实施者自行编写，故下文数字只能称为**合成样本标签一致率**，不能宣称产品在真实投研信息流中已达到 90%。

本轮文本涵盖中文、英文、西班牙文、日文；每种语言均有 `RESEARCH / KEEP / SKIP`，并与半导体、生物科技、零售、电网、太阳能、银行、航运、医疗器械等不同 Context 交叉。Context 包含研究领域、观察名单和不同投资期限。文件测试覆盖 PDF 与 Word。`source_type` 全部明确记录为 `self_authored_synthetic`，没有把自拟材料伪称为新闻、公告或研报。

## 具体发现

**v1 文本错误集中在 `KEEP → RESEARCH`。** 48 条中，`RESEARCH` 16/16、`SKIP` 16/16 与自拟标签一致，`KEEP` 10/16。中文 9/12、英文 12/12、西班牙文 10/12、日文 11/12。6 条错误的模型把握度为 0.26–0.74；把握度不是校准后的正确概率，不能直接当准确率。问题口径升级为 `triage-2026-09-20-v2`，明确“未来会议或结果发布日期本身、没有新实质信息和重大时间变化”应归 `KEEP`。

**v2 文本封存集为 48/48。** 三档各 16/16；四种语言各 12/12，四种新的 Context 各 12/12。整集 95% Wilson 区间为 **92.6%–100%**，单种语言仅 12 条，区间为 **75.8%–100%**。样本是刻意平衡且文本较短、线索较清楚的合成题，同一人编写标签与规则；这些区间只刻画本合成集合的抽样不确定性，不能消除样本选择和标注偏差。先前 v1 错判的 6 条 `KEEP` 做事后定向回归，v2 为 6/6；这组回归不算独立测试。

**文件路径暴露出额外边界。** 首组中、英、西、日语各一份 Word 与 PDF，8/8 的全文文字提取与原文一致，8/8 返回预设标签。进一步交叉 4 种语言、每种语言 2 个 Context、PDF/Word 和 `RESEARCH/KEEP` 的 16 份文件，提取 16/16 完整，但分类只有 14/16：西语医疗器械 PDF 和日语医疗器械 Word 中，只有早期概念展示、缺少性能或监管等关键数据，却被判 `RESEARCH`。这 16 份文件复用了 v2 封存集文字，**不能叠加到 48 条独立样本上计算准确率**。文件规则升级到 `triage-2026-09-20-v3`：与文本共享“现在是否有实质新增线索”的判断，再按整份文档的“至少一条重要线索”规则聚合。先前两份错判文件在 v3 事后定向回归为 2/2 `KEEP`，不算独立测试。

**v3 新文件封存集为 22/24（91.7%）。** 修改文件规则前冻结 24 份全新 PDF/Word 合成材料：四种语言、两个新 Context、三档各 8 条，每种语言的三档均跨 PDF 与 Word。离线提取 24/24 保留原文，24/24 实时请求返回三档。`RESEARCH` 8/8、`KEEP` 8/8、`SKIP` 6/8；PDF 12/12，Word 10/12；中文和英文各 6/6，西语和日语各 5/6。两条错误都在保险 Context：西语 `filehold-18` 把一条明确未显示保险关联的矿山测绘信息判为 `RESEARCH`（把握度 0.96），日语 `filehold-24` 把类似信息判为 `KEEP`（把握度 0.12）。同文字改为粘贴文本，仍分别得到 `RESEARCH` 和 `KEEP`，因此这两条不能归因于文件提取或全文聚合；更可能是模型对跨语言否定关联及 Context 边界的处理不足。这个原因是基于配对结果的推断，不是供应商内部诊断。整集 95% Wilson 区间 **74.2%–97.7%**，单语言仅 6 条，不能据此宣称每种语言都超过 90%。本批样本及错误已封存，不在它上面继续调规则。

另将旧合成样本中“长背景里只有一条重要线索”制成 Word，针对全文聚合规则做事后回归：v3 在 `whole_document_text` 范围返回 `RESEARCH`。这是一条功能检查，不能增加封存集样本数。

## 速度和连接

服务重启后旧 36 条的连接回归：36/36 返回三档，API 请求耗时 P50 **306 ms**、P95 **893 ms**。v1 多语言 48 条 P50 **336 ms**、P95 **838 ms**；v2 文本 48 条 P50 **310 ms**、P95 **740 ms**；v3 文件 24 份 P50 **348 ms**、P95 **892 ms**。这些是本机脚本到本地 API 的调用时间，包含本机提取与 Jev 但不含扩展 UI 操作；请求按约 2.2 秒间隔提交，不能说明高并发能力，也不能代替长期稳定性或产品端到端时延。成本未测。

## 后续正式验收

正式 90% 门槛仍为 **PARTIAL / 未验证**。需要从真实用户信息流按原始顺序取样，保留自然类别比例；覆盖不同语言、Context、投资期限、粘贴文本、PDF、Word 和扫描件；至少 20% 由两位研究员独立标注并裁决分歧。按实施方案，最终封存集建议至少 200 条且 `RESEARCH` 至少 50 条。同一事件、同一文档拆段和多语言改写应同组隔离。最终集只运行一次，分别报告三档正确率、`RESEARCH` 精确率和召回率、误 `SKIP`、可用率、文件提取保真度、真实端到端 P50/P95 与成本。每个拟宣称支持的语言须有足够的真实样本单独达到门槛；不能用合成集 100% 或整体平均代替。
